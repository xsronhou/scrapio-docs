## Credit system

Every API call consumes credits. Credits are deducted when a request completes successfully. Failed requests (4xx errors caused by bad input) are not charged.

Your balance resets monthly, at the start of your billing cycle. Credits do not roll over — unused credits expire at the end of the cycle, on every plan including paid ones.

### Proxy tiers and the `proxy` parameter on Fetch, Crawl, and Map

`Fetch`, `Crawl`, and `Map` accept an optional `proxy` field that controls how far a request may escalate to get past anti-bot defenses:

| `proxy` | What it does | Plans |
|---|---|---|
| `"basic"` | No proxy at all. If the target blocks it, the request fails with `proxy_required` and tells you to retry with `"auto"`. Billed at the base price. | All plans (the Free plan is always `"basic"`) |
| `"auto"` | The default on paid plans. Tries the cheap steps first and escalates to residential proxies only when needed, billed by the step that served the request. | Starter and higher |
| `"stealth"` | Skips straight to the strongest tier: a hardened browser behind a residential proxy. Use it when you already know a target needs it. The default `timeout_ms` is 20000 (10000 for the other modes) because this browser needs longer on heavy pages. | Starter and higher |

When every access attempt only times out, the response is `504 timeout` (not `502 target_blocked`) and asks for a larger `timeout_ms`; a `timeout_ms` above your plan's inline limit runs as an async job.

`use_proxy: true` is a deprecated alias for `proxy: "stealth"`. Sending `use_proxy: true` together with a different `proxy` value returns `400 invalid_request`. On the Free plan, `"auto"` and `"stealth"` return `402 plan_upgrade_required`.

Every Fetch response reports what the request cost in `usage`, for example `{ "credits": 15, "base": 5, "surcharge": 10, "tier": "proxy_browser" }`. The surcharge depends on the tier that actually served the request, not a flat rate:

| `usage.tier` | What served it | Surcharge |
|---|---|---:|
| `standard` | No proxy | +0 |
| `proxy` | Browser-less request through a residential proxy (no JavaScript) | +4 |
| `proxy_browser` | Real browser through a residential proxy | +10 |
| `stealth` | Hardened browser through a residential proxy | +65 |
| `cloudflare` | Cloudflare challenge solved with a real browser | +65 |

For Crawl and Map the surcharge applies per page/URL on top of the flat 2 credits: a 10-page crawl where 8 pages were served with no proxy and 2 needed the hardened browser bills `8 × 2 + 2 × (2 + 65) = 150` credits. `Interact` is billed at its flat per-session price and is not affected.

`Interact` accepts the same `proxy` field, with two modes depending on how you call it:

- **Prompt mode** (`prompt`): a single browser session with no ladder to escalate through, so it accepts `"basic"` (no proxy, the default) or `"stealth"` (residential proxy, +65 credits on top of the base 25). `"auto"` returns `400 invalid_request`.
- **Actions mode** (`actions`): `"auto"` (default on paid plans) uses the usual escalation ladder, `"basic"` never uses a proxy and skips the Cloudflare solver, and `"stealth"` goes straight to the hardened browser behind a residential proxy. A blocked `"basic"` request fails with `proxy_required`. Interact keeps its flat per-session price in every mode.

`use_proxy: true` also still works on Interact as an alias for `proxy: "stealth"`.

### Crawl and Map auto-promote to an async job on large requests

`Crawl` and `Map` normally run synchronously, fetching every page within the same HTTP request/response. If your request is large enough that it would plausibly exceed the tenant's inline execution budget — `max_pages`/`max_urls` above the surface's own default (25 for Crawl, 100 for Map), or an explicit `timeout_ms` above your plan's inline timeout — the API automatically queues it as an async job instead of holding the connection open, and responds the same way `POST /v1/jobs` does:

```json
{ "request_id": "...", "mode": "async", "status": "queued", "job_id": "...", "reason": "..." }
```

Poll `GET /v1/jobs/{job_id}` for the result, same as any other async job. Small/default requests are unaffected and stay synchronous — you can also opt into async explicitly at any size via `POST /v1/jobs` with `{ "kind": "crawl" | "map", "input": {...} }`.

If a request times out before the ladder would have reached its strongest tier, the `504 timeout` error includes a hint suggesting `proxy: "stealth"` or a higher `timeout_ms`, unless the request already set `proxy` to `"stealth"` or `"basic"` or is on the Free plan (where the hint wouldn't apply).

## Plan limits

| Plan | Monthly credits | Notes |
|------|--------------|-------|
| Free | 1,000 | Resets monthly. No proxy access — see below. |
| Starter | 25,000 | Unlocks dedicated APIs (Amazon, Walmart, Booking.com, Agoda, YouTube, Airbnb, Target, Reddit, TikTok, Apple App Store, Bing, ChatGPT, Perplexity, Gemini) and Fast Search. |
| Pro | 100,000 | Everything in Starter, plus Google SERP search. |
| Scale | 500,000 | Everything in Pro, plus custom rate limits. |
| Enterprise | Custom | SLA + dedicated capacity |

Credits do not roll over on any plan — unused credits expire at the end of the billing cycle.

### Free plan does not include proxy access

The Free plan never routes requests through a datacenter or residential proxy — only direct HTTP and stealth-browser access. Most targets work fine without either, but sites with stronger anti-bot defenses may block Free-plan requests that would succeed on a paid plan. When this happens, the API returns `free_plan_proxy_required` (see [Error Reference](/errors)) instead of a generic block, so you know upgrading is the fix rather than retrying.

### Dedicated APIs and Fast Search require a paid plan

Amazon, Walmart, Booking.com, Agoda, YouTube (search, video, subtitles, and search crawl), Airbnb, Target, Reddit, TikTok, Apple App Store, Bing, ChatGPT, Perplexity, Gemini, and Fast Search all require a Starter plan or higher. Google SERP search requires a Pro plan or higher. Requesting any of these on an ineligible plan returns `402 plan_upgrade_required`.

## Quota errors

When your credit balance runs out, the API returns:

```json
{
  "request_id": "...",
  "error": {
    "code": "credits_exhausted",
    "message": "Your plan's credit allowance has been exhausted. Buy a top-up or upgrade to continue."
  }
}
```

| Code | Status | When |
|------|--------|------|
| `credits_exhausted` | 402 | Balance is zero |

Credits are a hard cap, not billed overage — requests are blocked once your plan's included credits run out. Buy a top-up or upgrade to a higher plan to keep going.

## Checking your usage

Use the `usage` field in every successful inline response to see how many credits that call consumed:

```json
{
  "usage": { "credits": 5 }
}
```

Aggregate usage dashboards are available at [scrapio.dev](https://scrapio.dev).
